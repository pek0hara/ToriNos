# PCブラウザの左右サイドパネル設計

> **現在は無効**: 横長画面は全プラットフォームで `NavigationRail` + 本文（最大 760dp）の構成に統一したため、`sidePanelWidthFor` は常に `null` を返し、以下の 3 カラム表示は出ない（Issue #7）。実装は将来の再開に備えて残しており、以下は無効化前の設計記録である。

## 目的

PCブラウザの横長画面では、中央 640dp の列の左右が空白になっている。この余白を使い、プロフィールを左、設定と検索を右に表示する。中央のフィードを離れずに参照・操作できるようにする。

## 対象と切り替え条件

- Web版（`isWebPlatform`）だけを対象にする。モバイルとタブレットは既存のドロワーと画面遷移を維持する。
- 画面幅が `640dp + 左右 320dp` 以上のときにサイドパネル表示にする。パネル幅は `(画面幅 - 640dp) / 2` を 320〜480dp に収めた値とする。
- 条件を満たさない幅では既存の表示（中央列のみ、プロフィールはドロワー、設定と検索は画面遷移）のままにする。

## レイアウト

```
| 左パネル: プロフィール | 中央 640dp: 既存のアプリ | 右パネル: 設定・検索 |
```

- `App.kt` の `CenteredContentColumn` が幅を判定し、パネル幅を `LocalSidePanelWidth` で配下に渡す。パネル表示時は中央列を作らず、セッション側に全幅を渡す。
- セッション側（`AppSessionCoordinator`）の `SidePanelLayout` が左・中央・右を並べる。中央列は既存と同じく 640dp・`clipToBounds` とし、通知ドロワー・Snackbar・FAB・投稿画面・鍵設定は中央列の中に留める。
- 何も開いていないパネルは従来の余白と同じ見た目にする。
- 幅をまたいで変化しても中央の画面ツリーを作り直さないよう、中央列の呼び出し位置は条件分岐の外に固定する。

## 左パネル: プロフィール

- 既存のプロフィールドロワーの遷移状態（`DrawerCoordinator` の表示先と履歴）をそのまま使う。新しい状態を作らない。
- `DrawerCoordinator` に固定表示モード（`isDocked`）を追加する。固定表示中は、
  - プロフィールを開くとドロワーを動かさず表示先だけを切り替える。既に表示中なら履歴に積み、戻るで前の表示に戻る。
  - 履歴がない状態の戻るでパネルを閉じる（表示先を消す）。
  - 返信・設定・ジャーナルなど「ドロワーを閉じてから実行」する操作は、パネルを閉じずにそのまま実行する。
  - 通知を開いてもプロフィールは閉じない。
- ドロワーの中身は1つのComposableに切り出し、ドロワーと左パネルのどちらか一方だけで表示する。固定表示中はプロフィールドロワーのジェスチャーを無効にする。
- 固定表示に切り替わるときに開いているドロワーは表示先を残したまま閉じ、固定表示から外れるときに表示先があればドロワーとして開き直す。

## 右パネル: 設定と検索

- 右パネルは独自の履歴 `SidePanelNavigator` を持つ。表示先は 設定 / ミュートリスト / NGワード / リレー設定 / カスタム絵文字 / 検索。
- 歯車（全画面の設定ボタン、プロフィールの設定）と検索ボタン・ハッシュタグは、固定表示中なら右パネルを開く。設定と検索はパネルの履歴を置き換えて開く。連続で押しても重ならない。
- 設定から開く子画面（ミュート・NGワード・絵文字・リレー）はパネル内に積む。戻るで前に戻り、根元で戻るとパネルを閉じる。
- 検索結果のユーザーは左パネル、投稿・スレッドは中央の画面遷移で開く。
- プロフィールのビュー内（投稿詳細を含む）で押したカスタム絵文字は、そのビュー内に詳細を積む。詳細から戻ると元のプロフィール・投稿詳細に戻り、表示位置を維持する。
- ヘッダーのリレー設定・中央画面の本文の絵文字・投稿画面からの絵文字管理は、従来どおり中央の画面遷移とする。
- 各表示先は専用の `ViewModelStoreOwner` と保存状態を持ち、履歴から外れたときに破棄する。中央の画面遷移と同じ寿命にし、パネルを閉じて開き直すと初期状態から始まる。
- 固定表示から外れるとき、右パネルの履歴を中央の画面遷移に積み替えて同じ画面を表示し続ける。

## アカウント切り替え

左右パネルの状態はセッションのComposition内に置く。アカウント切り替えでセッションごと破棄され、別アカウントの画面が残らない。

## 受け入れ確認

1. PCブラウザ幅で、ヘッダーのアバターから左パネルにプロフィールが開き、中央のフィードは操作できる。
2. 左パネルでフォロー一覧・スレッド・他ユーザーへ進み、戻るで順に戻り、最後に閉じられる。
3. 歯車で右パネルに設定、検索ボタンで右パネルに検索が開く。設定の子画面は右パネル内で進み戻りできる。
4. 検索結果のユーザーが左パネル、投稿が中央に開く。
5. 狭い幅では従来どおりドロワーと画面遷移で表示される。幅を変えても中央の画面が初期化されない。

## 検証記録

### 設計レビュー

- 既存の `CenteredContentColumn` は 640dp をまたぐと `content()` の呼び出し位置が変わり、ナビゲーションを含む画面ツリーが作り直されていた。サイドパネルの閾値を足すと窓幅の変更で同じ問題が起きやすくなるため、App 側・セッション側とも中央の呼び出し位置を条件分岐の外に固定した。
- 投稿画面や鍵設定などセッション末尾のUIも中央列に残すため、`SidePanelLayout` はセッションUI全体を中央に包む形にした。引用・カスタム絵文字の CompositionLocal はパネル側にも同じ値を渡す。

### 実装レビュー

- 右パネルの画面の ViewModel と保存状態は、画面が Composition から抜けた後（`SideEffect`）に破棄する。狭い幅への切り替えとセッション終了では `disposeAll` で即時に破棄する。
- `DrawerCoordinator` の `isProfileDocked` のセッターと切り替えメソッドが JVM 上で同じシグネチャになるため、メソッド名を `updateProfileDocking` にした。
- 未表示の左パネルに背景色を塗っていたため、表示先があるときだけ塗るように修正した。

### ブラウザ確認（ヘッドレス Chrome、未ログイン、EVENT 送信は遮断）

- 1440px: 投稿者アイコンで左パネルにプロフィール、検索ボタンで右パネルに検索、サービスの歯車で右パネルに設定が開く。
- 設定 → NGワード → 戻る → 戻るで、設定に戻ってからパネルが閉じる。右パネル表示中も中央の画面遷移ができる。
- 検索結果のユーザーは左パネル、投稿は中央のポスト詳細に開く。
- 1440px → 900px: 左パネルのプロフィールはドロワーとして開き直し、右パネルの NGワードは中央の画面遷移に引き継がれる。1440px に戻すと左パネルに戻り、中央の画面は作り直されない。
- 未確認: ログイン状態での自分のプロフィール（アカウント切り替え・プロフィールからの設定）。
