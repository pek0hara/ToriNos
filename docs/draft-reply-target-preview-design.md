# 返信の下書きを読み込んだら返信先を表示する

## 目的
返信の途中で下書き保存すると、返信先（返信する投稿の ID・投稿者・スレッドの起点）も一緒に保存され、読み込むとその返信先への返信として復元される。
ところが下書きには返信先の本文がないので、投稿シートに「返信先」の欄が出ない。何への返信か確かめられないまま送ることになる。下書き一覧でも、返信の下書きかどうかがわからない。

読み込んだ下書きに返信先があれば、その投稿を取得して「返信先」の欄に出す。下書き一覧の行にも返信だとわかる表示を付ける。

## 今の動き
- `PostSheet` は、下書き一覧から選んだ下書き（`selectedDraft`）があると、返信先をその下書きの `restoreReplyTarget` に置き換える。
- 「返信先」の欄は、呼び出し元から渡された本文（`replyToPreview`）だけで出している。下書きを選ぶと `replyToPreview.takeIf { selectedDraft == null }` で消す（別の投稿の本文を出さないため）。
- カスタム絵文字設定へ移る間に退避したローカル下書き（`initialMemo`）を戻すときは、返信を開いた元の `replyToPreview` が残っていれば出るが、返信先は下書きから戻している。

## 変えないもの
- 返信中に別の下書きを読み込むと、返信先はその下書きのものに切り替わる（ふつうの投稿の下書きなら返信先は外れる）。下書きは「書きかけの投稿を丸ごと再開する」ものとして扱う。
- 下書きの保存形式。返信先の本文は保存しない。他のクライアントが保存した標準形式（NIP-37）の下書きでも同じように出せるよう、表示のたびに取得する。

## 方針

### 返信先の欄に出す本文
表示する返信先と本文の組を1つにまとめ、ずれないようにする。

| 状況 | 返信先 | 欄の本文 |
|---|---|---|
| 下書きを選んでいない、呼び出し元の本文あり | 呼び出し元 | 呼び出し元の本文（今どおり） |
| 下書きを選んでいない、本文なし（ローカル下書きの復元など） | 下書き | 取得した本文 |
| 下書きを選んだ、返信先あり | 下書き | 取得した本文 |
| 下書きを選んだ、返信先なし | なし | 欄を出さない |

取得中・失敗時も欄は出し、返信であることは常にわかるようにする:
- 取得中: 「読み込み中…」
- 取得できた: 投稿の本文。空なら `投稿 xxxxxxxx`（引用と同じ書き方）
- 取得できなかった: 「返信先の投稿を取得できませんでした」

### 取得のしかた
- `EventByIdFetcher` で ID 指定の有限取得をする。まず有効なリレー全体（`RelayTarget.AllEnabled`）、見つからず、復元した返信先にリレーの指定（`parent.relayUrl`、下書きの `replyParentRelayUrl` から戻る）があれば、そのリレーにも問い合わせる（記事エディタの引用取得と同じ順）。`wss://` で始まらない指定は使わない。
- 取得した投稿の ID が返信先の ID と一致するものだけ使う（`EventByIdFetcher` が署名と ID を検証済み）。
- 返信先の ID が64桁の16進でない場合は取得せず、失敗表示にする。
- 下書きを選び直したら、前の取得は捨てる（取得はシートの合成の中で返信先 ID をキーにして走らせ、キーが変われば取り消される）。

### 取得を担う部品
UI から切り離してテストできるよう、取得と表示文の決定を `ReplyPreviewLoader`（`ui/post/`）にまとめる。

```kotlin
internal sealed interface ReplyPreview {
    data object Loading : ReplyPreview
    data class Loaded(val text: String) : ReplyPreview
    data object Unavailable : ReplyPreview
}

/** 返信先の投稿を取得して、返信先の欄に出す本文を決める。 */
internal suspend fun loadReplyPreview(
    parent: ReplyEventReference,
    fetch: suspend (ids: Set<String>, target: RelayTarget, onEvent: (NostrEvent) -> Unit) -> Unit,
): ReplyPreview
```

`PostSheet` では、表示する本文を次のように決める:
- 呼び出し元の本文が使える（下書き未選択で `replyToPreview` が空でない）→ それを出す
- それ以外で返信先がある → `produceState(ReplyPreview.Loading, parent.id) { value = loadReplyPreview(...) }`
- 返信先がない → 欄なし

`PostSheetContent` の引数は文字列のままにし、上の3状態を文字列に直して渡す（見た目は今の欄と同じ）。

### 下書き一覧
- 返信の下書き（`replyToId` がある）の行は、本文の上に小さく「返信」と出す（`labelSmall`、`onSurfaceVariant`）。
- 一覧で返信先の本文までは取得しない。下書きの件数ぶん通信が増えるため。

## 受け入れる差
- 返信先の本文は、呼び出し元から渡されるときは表示用に整えた文字列、取得したときは投稿の `content` そのままになる。`nostr:` の参照などが生のまま出ることがあるが、欄は3行で省略するので確認用には足りる。
- 取得はシートを開くたび・下書きを選ぶたびに行う。返信先の欄のための1件だけなので、キャッシュは持たない。

## テスト（先に書いて失敗を確認する）
`ReplyPreviewLoaderTest`（`commonTest/.../ui/post/`）:
1. 有効なリレーで見つかった本文を返す。
2. 本文が空なら `投稿 xxxxxxxx` を返す。
3. 有効なリレーで見つからず、返信先のリレーがあればそこにも問い合わせ、見つかった本文を返す。
4. どこにもなければ `Unavailable`。返信先のリレーがない、または `wss://` でなければ2回目は問い合わせない。
5. ID が不正なら問い合わせず `Unavailable`。
6. 別の ID の投稿が返っても使わない。

表示の選び方（上の表）は純粋関数 `replyPreviewSource(selectedDraft, replyToPreview, replyTarget)` にし、`PostSheet` から切り出してテストする:
7. 下書き未選択・本文あり → 呼び出し元の本文。
8. 下書き選択・返信先あり → 取得する返信先。呼び出し元の本文は使わない。
9. 下書き選択・返信先なし → 欄なし。
10. 下書き未選択・本文なし・返信先あり → 取得する返信先。

## 確認
- `./gradlew :composeApp:iosSimulatorArm64Test`。
- 実機: 返信中に下書き保存 → 新規投稿で開いて下書き一覧（「返信」表示）→ 読み込むと返信先の欄が出る。`docs/regression-test.md` に追記する。
