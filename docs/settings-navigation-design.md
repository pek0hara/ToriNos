# 設定と管理機能のナビゲーション設計

## 目的

設定ダイアログと「すべての設定」の二段階構成を廃止し、歯車から設定画面に直接遷移する。設定を管理機能の総合入口とし、利用場面からのショートカットも用意する。本書は継続的に参照するUIの構成・遷移要件として保持する。

## 入口と画面構成

| 機能 | 日常利用の入口 | 設定からの入口 |
| --- | --- | --- |
| アカウント切り替え | マイプロフィール上部の「アカウント切り替え ▾」 | アカウント管理セクション |
| 投稿先リレー | 既存のヘッダー導線 | リレー → 投稿先リレー |
| ミュートリスト | 設定のみ | フィルタリング → ミュートリスト |
| カスタム絵文字 | サービス → 絵文字、ピッカー → 絵文字を追加、本文中の絵文字 | 絵文字 → カスタム絵文字 |

設定の分類は「表示・投稿」「フィルタリング」「絵文字」「リレー」「アカウント管理」「鍵」「アカウント」とする。既存の保存済みアカウント一覧はアカウント管理として維持し、切り替え・追加・保存済みアカウント削除を行う。鍵の開示・コピー、ログアウト、アカウント削除の既存動作は維持する。

## マイプロフィール

名前や画像の編集領域を切り替え操作に兼用しない。プロフィール情報と統計の間に文字付きのボタンを置く。通常のプロフィール画面とプロフィールドロワーの両方に配置する。

切り替えボタンからボトムシートを開く。アバター・表示名・短縮公開鍵・選択中のチェック・ログアウト済み表示を一覧化し、末尾に「アカウントを追加」を置く。削除・鍵管理は置かない。処理中は重複操作を無効化し、失敗時はシート内にエラーを表示する。閉じた場合はプロフィールに戻る。切り替え成功時はシートを閉じ、既存のセッション切り替えに従う。

## サービスの絵文字タブ

サービスは「記事 / チャンネル / ステータス / 絵文字」の4タブとする。既存の公開セット検索・登録・お気に入り機能を再利用し、別の実装を作らない。サービスから開く画面は共通形式のヘッダーとサービスタブを持ち、その下に検索欄と1つのセット一覧を配置する。登録済みセットは一覧の「登録済みのみ」フィルターで絞り込む。ヘッダーにプロフィール、単一の閲覧リレー選択、設定の操作を置く。再読み込みは一覧内の操作行に配置する。

絵文字探索は選択した1リレーから公開セットとフォロー先の公開登録情報を取得する。登録人数を一覧に表示し、フォロー内の登録順と新着・更新順を切り替えられる。自分の登録・お気に入りの同期先は既存設定を維持する。詳細は [`emoji-service-discovery-design.md`](./emoji-service-discovery-design.md) を参照する。

サービスタブ切り替えはタブタップで行う。

## 戻る操作と状態

- 設定の歯車は設定画面に直接遷移する。連続タップで同じ画面を重ねない。
- 設定 → 絵文字 → 戻るは設定に戻る。
- サービス → 絵文字 → セット詳細 → 戻るは絵文字一覧に戻る。サービスのヘッダーと4タブは詳細表示中も維持する。
- 本文の絵文字からは既存の対象セットへの遷移を維持する。
- ピッカーから管理画面を開いて戻る場合、投稿内容は保持する。既存のComposerの状態所有権を変更しない。
- プロフィールドロワーの設定操作はドロワーを閉じて設定画面を開く。
- ログイン前も表示・フィルタリング・絵文字・リレーの入口を利用できる。絵文字の変更操作は既存のログイン判定に従う。

## 受け入れ確認

1. 各画面の歯車が設定ダイアログを挟まず設定画面を開く。
2. プロフィールのボタンから切り替えシートを開閉でき、追加操作が既存の鍵設定へ接続する。
3. ミュートリストの管理入口は設定に集約される。
4. サービスの絵文字タブで検索・登録済み一覧・詳細への遷移が利用できる。
5. 設定とヘッダーの投稿先リレー操作が同じ画面を開く。
6. 設定から絵文字を開いて戻ると設定に戻る。
7. ピッカーから絵文字を開いた後も投稿内容が保持される。
8. iOSシミュレータでレイアウト、タブ切り替え、戻る操作を確認する。
