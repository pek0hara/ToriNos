# フッターの1段化と並び替え設定の設計

## 目的

フッターの「ホーム / ジャーナル / コンテンツ」と、コンテンツ内の「← / 記事 / チャンネル / ステータス / 絵文字」の2段切り替えをやめ、6機能を1段に並べる。幅に収まらないときはフッターを横にスライドして残りを出す。並び順と表示/非表示は設定で変えられる。

コンテンツ（記事・チャンネル・ステータス・絵文字）は左右スワイプで切り替えない。タブの切り替えは、ホームやジャーナルへの切り替えと同じフェードにする。

## 機能の定義

`FooterItem` を6つ定義する。コンテンツ系は既存の `ServiceTab` に対応づける。

| FooterItem | 保存ID | 行き先 | ServiceTab |
| --- | --- | --- | --- |
| Home | `home` | `feed` | なし |
| Journal | `journal` | `journal` | なし |
| Articles | `articles` | `services` | Articles |
| Channels | `channels` | `services` | Channels |
| Status | `status` | `services` | Status |
| Emojis | `emojis` | `services` | Emojis |

既定は上の順で、ホーム・ジャーナル・記事・チャンネルの4つを表示し、ステータスと絵文字は非表示にする。非表示の2つには別の入口を置く（後述）。

## 設定の保存

`DisplayPreferencesStore` に端末単位の設定として `footerItems`（`FooterConfig`：並び順と非表示の集合）を持つ。キーは `display_pref_footer_items_v1` で、値は保存IDをカンマでつなぎ、非表示の項目には先頭に `!` を付ける（例: `home,articles,!journal,channels,status,emojis`）。

読み込みは純粋関数 `FooterConfig.parse` で行う。

- 未知のID、重複は無視する。
- 保存値にない項目（将来の追加分）は、既定の順で末尾に、その項目の既定の表示状態で足す。
- ホームは常に表示にする（保存値で非表示でも表示に戻す）。
- 値がない・読めないときは既定にする。

ホームを非表示にできないのは、起動時の画面、最上位での Back の戻り先、各種「ホームへ戻る」の行き先がフィードに固定されているため。並び順は変えられる。これにより表示項目は常に1つ以上になる。

## フッターの表示

`AppBottomBarRow` を、項目数が幅に入らないときは横スクロールする1段のバーにする。項目幅は純粋関数で決める。

- `maxWidth / 項目数` が最小幅 72dp 以上なら、従来どおり均等に並べてスクロールしない。
- 下回るときは、72dp で入る数を `n`（2 以上に切り上げ）として、項目幅を `maxWidth / (n - 0.5)` にする。右端の項目が半分見えるので、続きがあることが分かる（360dp なら 4.5 項目、390dp なら 約86dp 幅で 4.5 項目）。
- ラベルの文字サイズは、従来どおり項目幅に収まる大きさをバー全体でそろえる。

選択中の項目が変わったら（戻る操作や通知からの遷移を含む）、その項目が見える位置までフッターをスクロールする。すでに見えていれば動かさない。

モード切り替えの横スライド（`AnimatedContent`、`FooterSwitch*` 定数）と「戻る」「コンテンツ」の項目は削除する。フィードでのスクロールに合わせた隠し方（`translationY`・`alpha`）は変えない。

### 選択状態

- ホーム: ルートが `feed`
- ジャーナル: ルートが `journal`
- コンテンツ系: ルートが `services` で `currentServiceTab` が一致。チャンネル詳細とチャンネル内スレッドではチャンネルを選択中とする（従来と同じ）。

### 横長画面（NavigationRail）

従来の「ホーム・ジャーナル | コンテンツ4つ」の区切りをやめ、フッターと同じ順序・同じ表示項目を1列で並べる。縦に入らないときのスクロールは従来どおり。

## タップ時の遷移

従来の `returnToMainTab`（「戻る」）と `selectServiceTab` のスタック処理を、1つの選択処理にまとめる。

1. 選択中の項目をもう一度押したとき: ホームは先頭へスクロール、ジャーナルはカレンダー切り替え（従来どおり）。コンテンツ系は何もしない。
2. 行き先のルート（`feed` / `journal` / `services`）がスタックにあれば、そこまで戻す。チャンネル詳細などの途中の画面は保存せずに閉じる。サービス外（フィードの上）から開いたチャンネル詳細でホームを押したときに、保存したスタックごと復元されて同じ画面に戻ってしまうのを防ぐ（従来の `returnToMainTab` と同じ理由）。
3. ない場合は、今いるタブの最上位まで戻してから、タブを切り替える（`navigateTopLevelRoute`）。どのタブにも属さない画面（URL から直接開いたチャンネル画面など）しかないときは、保存せずに閉じてから移動する（`closeOrphanPagesAndNavigate`）。
4. ジャーナルは従来どおり鍵が必要（`runWithPrivateKey`）。ホームへの切り替えは従来どおり `navigateFeedTab` を通す（Web 版はグラフの起点を残す特別な遷移、フィードのクローム表示の復帰を含む）。

「今いるタブの最上位」は、スタックにある `feed` / `journal` / `services` から求める。タブ切り替えは移動前に元のタブを取り除くので、通常はこのうち1つだけがスタックにある。Web 版では起点のフィードが他のタブの下に残ることがあるので、`services` → `journal` → `feed` の順に調べる。「戻る」と、その戻り先を覚えていた `lastMainRoute` は不要になるので削除する。最上位での Back（ジャーナル・コンテンツ → ホーム、ホームでは二度押しで終了）は変えない。

## コンテンツの切り替え

`services` は、選択中のコンテンツを1つだけ表示する。`HorizontalPager` と左右スワイプはやめ、切り替えは `AnimatedContent` のフェードにする。フェードは NavHost の画面切り替え（Navigation の既定と同じ 700ms のフェード）と共通の定義（`appScreenEnterTransition` / `appScreenExitTransition`）を使う。

- 読み込みや購読は切り替え先のタブだけが行う（`isActive`）。フェードで消えていくタブは止める。
- タブごとのスクロール位置などは `SaveableStateHolder` で残す。
- `currentServiceTab` が非表示の項目を指すとき（URL の `#channels` など、または設定で隠したとき）は、表示中の最初のコンテンツ系項目に寄せる。コンテンツ系が1つも表示されていないときに `services` へ来たら、ホームへ移る。
- チャンネル詳細（`ChannelRoute`）やチャンネル内スレッドは、チャンネルを非表示にしていても通知や本文のリンクから開ける。その画面では、フッターで選択中の項目がないこともある。

## 非表示のコンテンツへの入口

- ステータス: マイプロフィール右下の FAB で、単独のステータス画面（`status-page`、戻る付き）を開く。フッターの表示設定に関係なく開ける。自分のステータスの編集は、従来どおりプロフィールのステータス表示から行う。
- 絵文字: リアクション長押しのプルダウンの右上と、絵文字を選ぶシートの右上に「絵文字セット」ボタンを置き、絵文字セット画面（`CustomEmojiRoute`）を開く。投稿欄のシートでは、従来の下部の「絵文字を追加」をこのボタンにまとめ、下書きを守ってから開く処理はそのまま使う。

## 設定画面

設定の「表示・投稿」の次に「フッター」セクションを置き、画面遷移なしでその場で編集する。6行を現在の並び順で並べ、各行に次を置く。

- アイコンとラベル
- 上へ・下へのボタン（端の行では無効）
- 表示のスイッチ（ホームは常にオンで無効）

末尾に「初期設定に戻す」を置く。変更はその場でフッターに反映し、保存する。並び替えの操作（上下移動・表示切り替え・初期化）は `FooterConfig` の純粋関数にする。

## テスト

`commonTest` に純粋ロジックのテストを先に書く。

- `FooterConfig.parse` / `serialize`: 既定、往復、未知ID・重複・欠けた項目、ホームの非表示指定、空文字・壊れた値
- 上下移動（端では変わらない）、表示切り替え（ホームは変わらない）、初期化
- 項目幅: 収まる場合は均等でスクロールしない、収まらない場合は半分見える幅、項目数0・1
- 表示中のコンテンツ一覧（フッター順・非表示を除く）と、非表示の `currentServiceTab` を寄せる処理

画面の動作は iOS シミュレータと Web 版（ヘッドレス）で確かめる。

- 縦向きのスマートフォン幅でフッターが横にスライドし、右端が半分見える
- フッターからコンテンツを移ると、フェードで切り替わり、選択中の項目が見える位置までフッターが動く
- フィード上のチャンネル詳細・サービス内のチャンネル詳細から、各項目を押したときの戻り先
- 設定で並び替え・非表示にした結果が、フッターと横長画面のレールにそろって反映され、再起動後も残る

## 次の段階: 既定で非表示の項目

マイプロフィール・検索・通知・設定を、既定で非表示の項目として追加し、設定で表示に切り替えられるようにする（未着手）。

- `FooterItem` に `defaultVisible = false` で足す。保存値にない項目は既定の表示状態で末尾に足すので、既存の利用者のフッターは変わらない。
- 通知は既存のドロワーを開く操作、マイプロフィールは自分のプロフィール、検索は検索画面、設定は設定画面を開く。画面を切り替えずにドロワーを開く項目の選択状態と、横長画面で右パネルに開く項目の扱いは、追加時に決める。
