## 2. 合わせたときに直したところ

署名の変更とリファクタリングは、同じファイル 11 個を触っていましたが、3方向マージは衝突なく当たりました。コンパイルで、リファクタリング側で新しく書かれた次の箇所が、suspend にした署名・復号を suspend でない場所から呼んでいたので直しました。**マージするときに同じ修正が要ります。**

| ファイル | 修正 |
| --- | --- |
| `article/ArticleDraftRepository.kt` | 読み込み中の局所関数 `decode` を `suspend` にし、`mapNotNull(::decode)` を `mapNotNull { decode(it) }` にした |
| `ui/timeline/SignedEventPublisher.kt` | `prepare` を `suspend` にした（呼び出し元の `ChannelPublicationService` は `Mutex.withLock` の中なのでそのまま呼べる） |
| `commonTest/.../ChannelPublicationServiceTest.kt`、`DraftMemoRepositoryTest.kt` | テスト用の署名器を新しい型（`nip44Encrypt`・`nip44Decrypt`・`suspend fun sign`）に合わせた |
| `commonTest/.../ArticleDraftRepositoryTest.kt` | テスト内の補助関数 `draftEvent` を `suspend` にした |

- `Nip46Test`: `bunker://` の解析と検証、`nostrconnect://` の組み立て、署名する kind が権限にすべて入っていること、接続（secret と権限を送る）、署名と結果の検証、改ざんされた署名の拒否、`auth_url` の承認待ち、応答なしのタイムアウトと自動で再送しないこと、拒否、別の鍵からの応答を無視、セッション終了、`nostrconnect://` で secret の一致を待つこと。偽の署名器は実際の鍵で NIP-44 暗号化・署名して応答する。

## 4. Android 実機での確認

端末: ASUS Zenfone 10（AI2302）、ワイヤレス adb。アプリは「合わせたもの」のデバッグ版を、既存のアプリ（1.11.0）に上書きインストールした（データは残る）。アカウントは既存の秘密鍵アカウント1件。

あなたのアカウントで公開されてしまう操作（投稿・リアクション・リポストの送信、下書きの保存・削除）は行っていません。秘密鍵がスクリーンショットに写るので、設定の「表示」も押していません。

### 4.2 署名の変更で変わったところ

| --- | --- | --- |
| S1 | 既存の秘密鍵アカウントで起動 | 保存形式の移行なしで読み込めた（`session start method=PrivateKey`）。非公開ミュートリストも新しい suspend の経路で復号できた |

### 4.3 実機で見つかった問題と修正

| # | 問題 | 修正 |
| --- | --- | --- |
| D1 | **重大**: 秘密鍵で保存済みのアカウントと同じ公開鍵で NIP-46・NIP-07 にログインすると、保存していた秘密鍵が接続情報で上書きされて消える | `AccountLogin.saveExternalAccount` で、同じ公開鍵が秘密鍵（パスキーで保護したものを含む）で保存済みなら止める（S8 で確認） |
| D2 | `nostrconnect://` を同じ端末の署名アプリで承認すると、その間 ToriNos が裏に回って端末の省電力機能で通信が止まり（`UnknownHostException`）、応答を取りこぼす。NIP-46 の応答（kind 24133）はリレーに残らない一時的なイベントなので、後から取り直せない | ダイアログに「同じ端末の署名アプリでは `bunker://` を貼り付ける」案内を出した。根本の対策は NIP-55（段階4） |
| D3 | 利用条件への同意を、NIP-46 の接続が済んだ後に求めていた（断ると署名器に接続だけが残る） | ダイアログを開く前に同意を求めるようにした |
| D4 | 「コピー」「署名アプリで開く」のボタンの文字が、幅が足りず折り返す・切れる | 2つのボタンを縦に並べた |
| D5 | 署名アプリが入っていないとき「署名アプリで開く」が無反応 | 「署名アプリが見つかりません。コピーして…」と出す |

### 4.4 確認できなかったこと

- **NIP-46 での署名・暗号化（`sign_event`・`nip44_*`）の実機での動作。** 端末の Amethyst には ToriNos に秘密鍵で保存済みの「ペコ」しかなく、D1 の上書き防止で止まるため、NIP-46 のアカウントでセッションを始めていない。別のアカウントを Amethyst か nsec.app に用意して確かめる必要がある。
- `nostrconnect://` での接続の完了（D2 のため）。`wss://relay.nsec.app` はこのネットワークからは Mac・端末とも接続できなかった。
- Web（NIP-07・パスキー）と iOS の実機・実ブラウザ。
- 投稿・リアクションなど、公開される操作での署名の失敗と、楽観的な表示の戻り。

## 5. ログの出し方

- 署名: `[Signer]`（`util/PlatformLog.kt` の `isSignerTraceEnabled`、今は `true`）。セッションの署名方式、秘密鍵での署名・暗号化の kind、NIP-46 の要求・応答（ID・方式・所要時間・失敗の種類）、受信したイベントの送り手と照合結果、パスキーの解錠、署名器の状態の変化を出す。鍵・本文・暗号文は出さない。**リリース前に `false` に戻すか、`ToriNosRefactor` と同じく `setprop` で切り替える形にする。**
- リファクタリング: `adb shell setprop log.tag.ToriNosRefactor DEBUG`（既存）。
- 見方: `adb logcat | grep -E "\[Signer\]|ToriNosRefactor|\[Journal\]"`
