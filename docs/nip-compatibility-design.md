# NIP互換性の設計

## 対象と根拠

2026-10-03のソースレビューで確認した5件（下書き形式、チャンネルのリポストkind、リポストのrelay hint、空文字リアクション、Bech32混在表記）を対象とする。既存の編集中データを維持する。

- [NIP-37](https://github.com/nostr-protocol/nips/blob/master/37.md): kind 31234、必須kタグ、NIP-44自己暗号化した未署名イベント。
- [NIP-18](https://github.com/nostr-protocol/nips/blob/master/18.md): kind 1には6、それ以外には16、eタグの取得先URL。
- [NIP-25](https://github.com/nostr-protocol/nips/blob/master/25.md): +と空文字はいいね。
- [NIP-19](https://github.com/nostr-protocol/nips/blob/master/19.md)、[BIP-173](https://github.com/bitcoin/bips/blob/master/bip-0173.mediawiki): Bech32の混在表記を拒否する。

## 下書きの保存・復元

PostDraftCodecに形式変換を集約する。新規保存はpubkey、created_at、kind、tags、contentを持つ未署名イベントをJSON化し、自己暗号化する。外側はd、k、clientタグを持つ31234。本文・画像URL・引用・返信・content-warning・emoji・imetaは実投稿と同じ組み立て規則を使う。torinos拡張に編集用情報（本文と添付画像の分離、引用プレビューなど）を保存する。

復元は標準形式を先に読む。pubkeyと外側の所有者、kindとkが一致し、対応kind（1、42、1111）であることを確認する。拡張は本文・kind・タグとの整合を検証し、合わなければ標準フィールドから復元する。記事30023は記事リポジトリに任せる。標準形式には画像URLが本文に含まれるため、追加の添付として復元して二重掲載しない。

旧PostMemoPayloadも読み込みを維持し、再保存時に同じdで標準形式へ移行する。不正な標準形式を旧形式として読み直さない。取得イベントを先に所有者・kindで絞り、最新版を暗号化解除より先にpubkey/kind/d単位で選び、空content（削除済み）が旧版を復活させない。既存の明示削除はNIP-09を維持する。

kind 10013の専用私有リレー、expiration、checkpointは今回の対象外（推奨・任意機能）。保存先設定は維持する。

## リポスト

NoteEngagementServiceで対象kindに応じて6/16を選ぶ。16にはkタグ、addressable/replaceableイベントにはaタグも付ける。保護イベント（-タグ）は本文を空にする。

取得先URLは実際に対象イベントを受信したリレーを使う。EventRelayHintStoreは検証済み受信のID→URLをセッションメモリに最大10000件保持し、同期ロックで保護する。通常・一時接続の両方で記録する。キャッシュに無ければ2.5秒以内の有限取得で所在を確認し、それでも不明なら署名前に失敗させる。任意の書き込みリレーを取得先として捏造しない。

新しいkind 16をチャンネル集計、ジャーナル、自分の履歴、通知で読めるようにする。既存kind 6は読み込みを維持する。kind 1111のリポスト操作は従来どおり未対応。

## リアクション

NostrEvent.isLikeReactionを共通の判定にする。kind 7かつ本文が+または空文字ならtrue。既存のtrimによる扱いを維持する。フィード、詳細、チャンネル、検索、ジャーナル、記事、カードの分類と自分のいいね状態に共通適用する。絵文字、-、不明文字列はいいねに含めない。

## Bech32

小文字化する前に大文字と小文字の混在を拒否する。全大文字・全小文字は維持する。復号の余剰ビットも検証し、不正なパディングを黙って切り捨てない。

## 検証・完了条件

標準下書きの往復、旧形式復元、他クライアント形式、返信・画像・引用・警告、所有者/k不一致、記事分離、空contentの削除を検証する。リポスト6/16と必須URL、URL不明時の無送信、保護イベント、kind 16受信を検証する。空文字の件数・自分の状態、Bech32の大文字・混在・パディングを検証する。関連テストとAndroid/Wasmコンパイルを実施し、レビューで見つけた問題を修正して再検証する。
