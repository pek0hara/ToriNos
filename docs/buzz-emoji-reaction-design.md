# Buzz の絵文字リアクション 設計

- 作成日: 2026-11-18（同日、「通常フィードを踏襲する」方針で改訂）
- 対象: チャットタブのグループ（Buzz と標準の NIP-29。コミュニティの絵文字は Buzz だけ）
- 関連: [nip29-buzz-design.md](nip29-buzz-design.md)、[default-reaction-design.md](default-reaction-design.md)、[custom-emoji-refactor-design.md](custom-emoji-refactor-design.md)
- 調査対象: block/buzz `75d78ea`（2026-11-15）、block/buzz-app `456bc5e`（2026-11-16）

## 1. 目的と方針

1. メッセージを長押ししたとき、最近使った絵文字を並べ、1タップでリアクションできるようにする。
2. コミュニティ（Buzz のリレー）に登録されたカスタム絵文字でリアクションできるようにする。

**基本は通常フィードの部品と動きをそのまま使う。** 新しく作るのは、コミュニティの絵文字の取得と、それをフィードの部品に差し込む口だけにする。フィードと違う動きにするのは、Buzz の仕様や限定公開の画像のために、そのままでは困るところだけ（4.7 にまとめる）。

## 2. 現状

### 2.1 チャット

- 長押しメニューの「👍 リアクション」は `+` だけを送る（`GroupChatScreen.kt` の `actions.onReact` → `GroupChatViewModel.toggleReaction(message)`）。
- 表示は対応済み。`GroupTimeline` がリアクションを本文ごとに集計し、`emoji` タグの画像を `emojiUrl` に入れる。`/media/` の画像は `rememberEmojiImages` が Blossom 認証を付けて読む。
- チップのタップで付け外しできる。1人が1つのメッセージに複数のリアクションを付けられる。

### 2.2 通常フィード（踏襲する元）

| 部品・動き | 場所 |
| --- | --- |
| リアクションのチップ。タップで付け外し。カスタム絵文字のチップの長押しで、その絵文字のセットを開く | `NoteEngagement.kt` の `ReactionChip` |
| チップの並びの最後の［＋］で `QuickReactionMenu` を開く。最近使った（最大16個、横スクロール）、右上に「絵文字セット」、下に「絵文字を選ぶ」 | `NoteEngagement.kt` の `QuickReactionMenu` |
| 「絵文字を選ぶ」で `StandardEmojiPickerSheet`（お気に入り → 最近使った → カスタム絵文字 → 標準カテゴリ、検索、デフォルトのリアクションの変更） | `EmojiPickerSheet.kt` |
| 送ったものを「最近使った」に記録する（アカウント全体、最大24個） | `CustomEmojiUi.kt` の `recordReactionUse` |
| 1人1投稿に1つまで（`hasOwnReaction` のとき他のチップと［＋］を無効にする） | `NoteEngagement.kt`、`NoteCardContent.kt` |
| ハートのタップでデフォルトのリアクションを送る | `NoteEngagement.kt` |

`QuickReactionMenu` は幅 280〜320dp、タイルは 40dp + 間隔 4dp なので、スクロールせずに見えるのは6個前後になる（「6個くらい」の要望と合う）。

## 3. Buzz のカスタム絵文字（調査結果）

### 3.1 コミュニティの絵文字の置き場所

| 方式 | 内容 | Buzz 側の状況 |
| --- | --- | --- |
| kind 30030、`d` = `buzz:custom-emoji` | メンバーがそれぞれ自分のセットを1つ出し、全員分の和集合を「コミュニティの絵文字」とする | buzz-app（`features/relay/emoji-directory.ts`）とCLIが使う現行の方式 |
| kind 30180（NIP-CE） | 1つの絵文字を1イベントにする。`#d` で名前を引くか、`POST /query` の前方一致検索で探す | リレーは受け付けるが、buzz-app はまだ読んでいない |

- 和集合の作り方（buzz-cli `emoji.rs` の `union_custom_emoji`、buzz-app も同じ）: shortcode ごとに `created_at` が新しいセットのものを採る。同時刻なら URL の小さい方。shortcode で並べる。
- shortcode は正規化してから使う: 前後の空白とコロンを除き、小文字にして `^[a-z0-9_-]{1,64}$` を満たさないものは捨てる。リレーは元のタグのまま保存するので、`"  :WAVE:  "` のような値が実際に来る。
- 取得は `{kinds:[30030], "#d":["buzz:custom-emoji"], limit:500}`。500件ちょうど返ったら「一覧が欠けているかもしれない」とみなす（buzz-app と同じ）。
- 画像の URL は多くがコミュニティの `/media/`（読むのに Blossom 認証とメンバー確認が要る）。

### 3.2 リアクションの受け付け条件と表示

- `content` は64文字（コードポイント）以内か、`:shortcode:`（`^:[a-z0-9_-]{1,64}:$`）。
- `emoji` タグの shortcode はリレーが正規化して検証する。正規化できないものは `invalid:` で拒否される（`ingest.rs` の `validate_custom_emoji_tags`）。4要素目（セットのアドレス）は見ない。
- メッセージやリアクションの `emoji` タグはそのまま（NIP-30）。履歴は一覧を引かずに表示できる。
- 例外: エージェントは `emoji` タグ無しの `:shortcode:` でリアクションする。buzz-app はこれをコミュニティの一覧から引いて画像にする（`reaction-emoji.tsx` の `useReactionEmoji`。タグがあればタグを優先）。
- buzz-app はリアクションを (本文, 画像の URL) の組で集計・取り消しする。送信中・結果不明の間は同じメッセージへの付け外しを止める（`MessageReactions.tsx` の `useReactionAction`）。
- buzz-app は1人が1つのメッセージに複数のリアクションを付けられる。

## 4. 方針

### 4.1 入口（フィードと同じ）

- チップの並びの最後に［＋］を置き、`QuickReactionMenu` と同じ中身を開く（フィードと同じ）。チャットではリアクションが1つも無いメッセージには出さない（すべての行に出ると読みにくいため。長押しで付けられる）。
- メッセージの長押しメニューにも同じ並びを出す。長押しメニューの先頭に `QuickReactionMenu` の中身（最近使った + 「絵文字を選ぶ」）を置き、その下に返信・コピー・編集・削除を続ける。「👍 リアクション」の項目は消す。
  - そのために `QuickReactionMenu` の中身を `QuickReactionContent` として切り出し、フィードの［＋］のメニューと長押しメニューの両方で使う。フィードの見た目は変えない。
- 書き込めないとき（`canWrite` が偽）は［＋］も並びも出さない。

### 4.2 最近使った（フィードと同じ一覧を使う）

- アカウント全体の「最近使った」をそのまま使い、送ったときに `recordReactionUse` で記録する（フィードと同じ）。フィードで使った絵文字がチャットにも、チャットで使った絵文字がフィードにも出る。
- 例外はコミュニティの絵文字だけ（4.7 の1）。

### 4.3 ピッカー（フィードと同じシートに口を足す）

`StandardEmojiPickerSheet` に省略可能な引数を足す。フィードからは渡さないので、フィードの動きは変わらない。

- `communityEmojis: CommunityEmojiSection?`: 「このコミュニティ」のセクションを、お気に入りの前に出す。下の絞り込みボタンにも1つ足す。検索の対象にも入れる。
- `isSendable: (ReactionOption) -> Boolean`: 送れないものを出さない（4.6）。
- `imageHeaders: (url) -> Map<String, String>?`: `/media/` の画像に認証を付ける。タイル（`ReactionPickerTile`、`EmojiPickerGridTile`）にも渡す。
- デフォルトのリアクションの変更（`DefaultReactionPickerMode.Offer`）もフィードと同じく出す。

### 4.4 コミュニティの絵文字の取得（`chat/BuzzEmojiPalette.kt`）

- 段階1は kind 30030 だけを読む。kind 30180 は、buzz-app が使い始めたら、ピッカーの検索に足す。
- コミュニティ（リレー URL）ごとに、アカウントのセッション内でメモリに持つ。
  - 部屋を開いただけでは読まない。ピッカーを開いたときと、4.5 のタグ無しのリアクションを表示するときに読む。
  - 読み込み済みでも、5分たっていたら裏で読み直す。表示は前の一覧のまま。
  - 読めなかったら前の一覧を残す。一度も読めていなければ、セクションに「読み込めませんでした」と再試行を出す。空とは決めつけない。
- 純粋関数 `unionBuzzEmojiSets(events): BuzzEmojiPalette`（3.1 の規則、`truncated` フラグ付き）。
- 取得は `ChatAccount` に `fetchCommunityEmojis(relayUrl)` を足し、グループ作成の処理と同じ `fetchFiniteEvents`（AUTH 済みの接続）で読む。

### 4.5 表示

- チップは今の `GroupChatScreen` のまま（画像は `rememberEmojiImages`）。
- タグ無しの `:shortcode:` は、4.4 の一覧にあれば画像にする（buzz-app と同じ）。
- 集計と取り消しの単位を (本文, 画像の URL) にする。同じ shortcode で別の画像のものを1つにまとめない。

### 4.6 送信

- `buildGroupReaction(groupId, target, option: ReactionOption)` に変える。
  - Unicode: `content` = 絵文字。
  - Custom: `content` = `:shortcode:`（小文字）、`["emoji", shortcode, url]` を足す（自分のセットの絵文字はフィードと同じく4要素目にセットのアドレスを付ける）。
- 送れるかの判定 `isSendable`（純粋関数）:
  - Unicode: 64コードポイント以内。
  - Custom: 小文字にした shortcode が `^[a-z0-9_-]{1,64}$`。大文字はリレーが小文字にして受け付けるので、小文字にして送る。日本語などの shortcode の自分の絵文字は出さない。標準の NIP-29 では制限しない（フィードと同じ）。
- 送信中は、そのメッセージへの付け外しを止める（連打で、付けると取り消しが入れ違わないように。buzz-app と同じ）。

### 4.7 フィードと変えるところ

| # | フィードの動き | チャットでの動き | 理由 |
| --- | --- | --- | --- |
| 1 | 送った絵文字はすべて全体の「最近使った」に入る | コミュニティの絵文字は全体に入れず、コミュニティごとの「最近使った」に入れる。チャットの並びでは、コミュニティの「最近使った」を全体の「最近使った」の前に出す | メンバー限定の URL がフィードの一覧に入ると、フィードでは表示できず、公開のリアクションに使うと URL が外に出る |
| 2 | 1人1投稿に1つまで | 複数付けられる（今のチャットのまま） | Buzz では複数が普通で、他のクライアントの表示とも合う。**要確認（7章の1）** |
| 3 | カスタム絵文字のチップの長押しで、その絵文字のセットを開く | 自分のセットの絵文字（`emoji` タグに公開セットのアドレスがある）だけ開く。コミュニティの絵文字では何もしない | コミュニティのセットは公開リレーに無く、開いても読めない |
| 4 | ハートのタップでデフォルトのリアクション | ハートは無いので、長押しの並びとピッカーにデフォルトの変更だけ出す | チャットに対応するボタンが無い。**要確認（7章の2）** |
| 5 | 絵文字は制限なし | Buzz では 4.6 の条件外を出さない | リレーに拒否される |

コミュニティごとの「最近使った」は `LocalSettingsStorage` にアカウント × コミュニティで保存し、最大24個、`RecentReaction` の形（Unicode / Custom(shortcode, url)）を使い回す。

### 4.8 画像の署名（実装で決めたこと）

- ピッカーと並びのタイルは `LocalEmojiImageHeaders`（URL → ヘッダー、null なら `:shortcode:` の文字）を見る。既定はそのまま読むので、フィードは変わらない。
- チャットの画面は、長押しメニュー・［＋］のメニュー・ピッカーが開いている間だけ、コミュニティのホストの読み取り証明を用意し、45秒ごとに作り直す（期限は55秒）。開いていない間は署名しない（外部署名器で、許可した後に署名が続かないように）。
- チップの画像は今までどおり `rememberEmojiImages`。

| 段階 | 内容 |
| --- | --- |
| 1 | 純粋ロジック（和集合、`isSendable`、並びの組み立て、コミュニティごとの「最近使った」の保存）とテスト |
| 2 | 送信（`buildGroupReaction` のカスタム絵文字対応、集計の単位、送信中の付け外しの抑止）とテスト |
| 3 | `QuickReactionContent` の切り出し（フィードの見た目が変わらないことを確認）と、チャットの［＋］・長押しメニュー |
| 4 | ピッカーの引数追加、コミュニティの絵文字の取得、タグ無しの表示 |
| 5 | Android 実機とローカルの buzz-relay で確認（取得件数、`/media/` の画像、拒否が出ないこと、フィードが変わっていないこと） |
| 後で | kind 30180 の検索（buzz-app の対応を待つ） |

## 6. テスト

- `unionBuzzEmojiSets`: 新しいセットが勝つ、同時刻は URL の小さい方、正規化（`"  :WAVE:  "` → `wave`）、不正な shortcode・空 URL を捨てる、同じイベント内の重複は先勝ち、500件で `truncated`。
- `isSendable`: 64コードポイントの境界、合成絵文字（家族の絵文字など）、Buzz で大文字・日本語の shortcode を弾く、標準の NIP-29 では弾かない。
- 並びの組み立て: コミュニティの「最近使った」→ 全体の「最近使った」の順、重複除去、送れないものを飛ばす、16個に切る。
- 記録: Unicode と自分の絵文字は全体に、コミュニティの絵文字はコミュニティにだけ入る。アカウント・コミュニティごとに分かれる。壊れた保存値を無視する。
- `buildGroupReaction`: Custom で `emoji` タグが付く、shortcode が小文字になる。
- `GroupTimeline`: 同じ shortcode で URL が違うリアクションが別に集計される。タグ無しの `:shortcode:` が一覧で画像になる。

## 7. 決めること

1. 1人1メッセージに1つまで、をフィードに合わせるか（4.7 の2）。設計では今のチャットのまま複数にしている。
2. デフォルトのリアクションをチャットでどう使うか（4.7 の4）。案: 長押しの並びの先頭に固定で出す / 使わない。
3. Buzz で自分の絵文字セット（外部 URL の画像）を使えるようにするか。設計では、shortcode の条件を満たすものは使えるようにしている（フィードと同じ一覧から出るため）。
4. Buzz 送信時の `p`・`k` タグ。今は付けていて拒否されていない。nip29-buzz-design 6.8 は「`e` と `h`」。実機で確かめてから決める。

## 8. 範囲外

- 投稿欄での `:shortcode:` 補完にコミュニティの絵文字を出すこと（buzz-app にはある）。リアクションの後で別に扱う。
- コミュニティへの絵文字の登録（自分の kind 30030 `buzz:custom-emoji` を出すこと）。
- ハドルの一時的なリアクション。

## 9. レビュー（作成後の自己確認）

- フィードの部品を変えるのは、`QuickReactionMenu` の中身の切り出しと `StandardEmojiPickerSheet`・タイルへの省略可能な引数だけ。フィードからは新しい引数を渡さないので、動きは変わらない。段階3と5でフィードの見た目を確かめる。
- 長押しの並びは一覧の取得を待たない（「最近使った」は URL ごと保存してあるため）。部屋を開くたびに 500 件読むことはしない。
- 削除・差し替え済みのコミュニティの絵文字が「最近使った」に残る点: 送ると古い URL のリアクションになるが、表示はリアクション自身の `emoji` タグを使うので壊れない。一覧を読めたときに一覧に無いものを落とすかは段階4で決める（読めなかったときには落とさない）。
- 画像の署名: 読み取り証明は `BlossomTokenCache` でホストごとに使い回すので、並びを出すたびに署名が増えることはない。外部署名アプリでは今と同じく、許可までは `:shortcode:` の文字で出す。
