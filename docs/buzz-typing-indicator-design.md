# Buzz の入力中表示 設計

- 作成日: 2026-11-17
- ステータス: 実装済み（Android 実機と Buzz 公式アプリの間で両方向を確認済み）
- 目的: Buzz のチャンネル（チャット・スレッド）で、ほかの人が入力中であることを入力欄の上に「〇〇さんが入力中…」と出す。自分が入力しているときは、そのことを Buzz の形式で送る。
- 対象: Buzz のコミュニティだけ。標準の NIP-29 リレーでは送らず、表示もしない（kind 20002 は標準に無く、拒否するリレーがあるため）。
- 調査対象: [block/buzz-app](https://github.com/block/buzz-app)（2026-11-16 時点）の `src/features/relay/typing-protocol.ts`、`relay/typing.ts`、`relay/session.ts`（`typing.send`）、`messages/useTypingBroadcast.ts`、`agents/typing.ts`。[block/buzz](https://github.com/block/buzz) の `NOSTR.md`、`crates/buzz-relay/src/handlers/event.rs`（2026-11-15 時点）。
- 関連: `docs/nip29-buzz-design.md`（チャットタブと Buzz 対応の全体）。

## 1. Buzz の仕様

### 1.1 イベント

| 項目 | 値 |
| --- | --- |
| kind | 20002（保存されない、ephemeral の範囲） |
| content | 空文字。下書きの中身は送らない |
| タグ | 先頭に `["h", チャンネルID]`（1つだけ）。スレッドの中では `["e", ルートID, "", "reply"]` を足す。エージェントは入れ子のとき `["e", root, "", "root"]` と `["e", 親, "", "reply"]` の2つを付ける |

- リレーは保存せず、そのチャンネルを `kinds` に 20002 を含む `#h` 付きの購読に配る。送信には `OK` を返す（`handle_ephemeral_event`）。
- 書き込み権限の無い人の送信は断られる（`enforce_write_restriction`）。

### 1.2 送る側（`useTypingBroadcast.ts`、`session.ts`）

- **ユーザーが入力欄を編集したときだけ**送る。定期的な送信や、失敗したときの送り直しはしない。
- 同じ画面では、前回から **3秒** 経つまで送らない。
- 失敗しても入力を妨げない（通知も出さない）。
- 署名に1秒以上かかったものは古いので送らない。
- 読み取り専用・アーカイブ済みのチャンネル、書けないチャンネルでは送らない。

### 1.3 受け取る側（`typing.ts`）

- 自分のものは無視する。
- `created_at` が未来、または **8秒** より前のものは無視する。
- `h` タグがちょうど1つで、チャンネルIDの形が正しいこと。`e` タグは2つまで、`reply` がちょうど1つ、`root` は1つまで（形が崩れたものは無視）。
- 表示の単位は「チャンネル + スレッドのルート（無ければチャンネル直下）+ 人」。ルートは `root` タグ、無ければ `reply` タグ（メッセージの `threadReference` と同じ）。
- 表示は受け取った入力中のイベントの時刻から 8秒。
- その人のメッセージ（kind 9・40002）が届いたら消し、**2秒** は次の入力中を出さない。メッセージより古い入力中は出さない。スレッドへの返信は、同じ人のチャンネル直下の入力中も消す。
- 記録は 1024 件まで（超えたら新しい単位を捨てる）。

## 2. ToriNos での方針

### 2.1 時刻の扱い

Buzz は相手の `created_at` から 8秒を数える。ToriNos では次のようにする。

- 入力中のイベントは保存されず、届くのは配信中だけなので、**表示の期限は受け取った時刻 + 8秒**とする。相手の端末の時計が数秒ずれていても表示が消えたり出なかったりしないようにするため。
- ただし `created_at` が受け取った時刻より **30秒** 以上古いもの・新しいものは捨てる（リレーの遅延した配信や、壊れた時計への備え）。
- 「メッセージより古い入力中は出さない」の比較は `created_at` 同士で行う（同じ人の端末の時刻なので比べられる）。

### 2.2 送る条件

次のすべてを満たすときだけ送る。

1. Buzz のチャンネルで、画面がチャットかスレッド（フォーラムの一覧では送らない）。
2. 投稿欄が書ける状態（`GroupComposerState.Writable`）。
3. **確認なしで署名できるアカウント**（秘密鍵・パスキー。`ChatAccount.signsSilently`）。外部の署名器（Amber・NIP-46）では、3秒ごとに署名の確認が出てしまうので送らない（表示は行う）。
4. 自分のメッセージの編集中ではない。
5. ユーザーの編集で、編集後の本文が空ではない（全部消したときは送らない）。
6. 前回の送信から 3秒以上経っていて、前回の送信が終わっている。

送信は `ChatAccount` の通常の送信（そのグループのリレーだけ、`auth-required:` で1回だけ送り直し）を使い、結果は無視する。`GROUP_PUBLISHABLE_KINDS` に 20002 を足す。

### 2.3 受け取り

- 画面の購読（`GroupChatViewModel.filters()`）に、Buzz のチャット・スレッドのときだけ `{"kinds":[20002],"#h":[グループID],"since":購読した時刻}` を足す。別の購読にはしない（同じ接続・同じ AUTH で済み、購読の数を増やさないため）。
- 20002 は `onEvents` の最初で取り分け、**画面の控え（`GroupRoomCache`）・タイムライン・過去の読み込みの起点には入れない**。
- メッセージ（kind 9・40002）は、配信中に届いたものと自分が送ったものを入力中の記録にも渡す（控えから出したものは渡さない）。
- 表示する人から、自分とミュートした人を除く。
- スレッドの画面ではルートがそのスレッドのもの、チャットの画面ではチャンネル直下のものだけを出す。
- 表示が変わる時刻（期限）に合わせて状態を更新する。

### 2.4 表示

- 入力欄の上（返信・編集の案内の上）に、小さな文字で1行出す。誰も入力していないときは何も出さない。
- 投稿欄が「参加すると書き込めます」などの案内のときも、読めているなら出す。
- 文言:
  - 1人: 「Aさんが入力中…」
  - 2人: 「AさんとBさんが入力中…」
  - 3人以上: 「Aさんほか2人が入力中…」
- 名前はプロフィールの表示名。無ければ公開鍵の先頭8文字。並びは入力中になった順（先に入力し始めた人が先）。
- 入力中の人のプロフィールは、メッセージの作者と同じくグループのリレーを先に聞いて取る。

### 2.5 やらないこと

- 標準の NIP-29 グループでの送受信。
- 入力中を送るかどうかの設定（Buzz のアプリにも無い。必要になれば足す）。
- フッターやグループ一覧での入力中表示（Buzz のアプリは一覧にも出すが、一覧はチャンネルごとの購読を持たないので見送る）。
- 在席表示（kind 20001）。

## 3. 構成

| 部品 | 場所 | 内容 |
| --- | --- | --- |
| 入力中のイベントの組み立て・解析・記録（純粋なロジック） | `chat/GroupTyping.kt` | `BUZZ_TYPING_KIND`、`buildBuzzTyping`、`buzzTypingScope`、`TypingThrottle`、`TypingTracker`、`typingLabel` |
| 送信の許可 | `chat/GroupMessages.kt` | `GROUP_PUBLISHABLE_KINDS` に 20002 |
| 購読・取り分け・送信・期限の更新 | `ui/chat/GroupChatViewModel.kt` | `typingAuthors`（状態）、`onInputEdited` |
| 表示 | `ui/chat/GroupChatScreen.kt` | `TypingIndicator` |

### 3.1 `TypingTracker`

```kotlin
class TypingTracker(viewer: String?, groupId: String) {
    fun receiveTyping(event: NostrEvent, nowMillis: Long): Boolean   // 表示が変わったら true
    fun receiveMessage(event: NostrEvent, nowMillis: Long): Boolean
    fun visible(threadRootId: String?, nowMillis: Long): List<String> // 入力中の人（入力中になった順）
    fun nextChangeAt(nowMillis: Long): Long?                          // 次に表示が変わる時刻
}
```

人と単位ごとに、`lastTypingAt`（秒）、`lastMessageAt`（秒）、`visibleUntil`（ミリ秒）、`quietUntil`（ミリ秒）、`since`（入力中になった時刻、並び順用）を持つ。期限が過ぎて静かになった記録は、受け取りのたびに消す。

## 4. テスト（先に書く）

`commonTest/.../chat/GroupTypingTest.kt`:

- 組み立て: チャンネル直下は `h` だけ、スレッドは `e` の `reply` を足す。content は空。
- 解析: 他のグループ、`h` が2つ、`e` が3つ、`reply` が無い・2つ、`root` が2つ、マーカーが不正、ID が64桁の16進でない、content が空でない → 捨てる。エージェントの `root` + `reply` はルートが `root` になる。
- 記録:
  - 受け取ると出て、8秒後に消える。
  - 自分のもの・30秒以上ずれたものは出さない（ミュートは画面の側で除く）。
  - その人のメッセージで消え、2秒は次の入力中を出さない。2秒後は出す。
  - メッセージより古い `created_at` の入力中は出さない。
  - スレッドへの返信で、同じ人のチャンネル直下の入力中も消える。他のスレッドのものは残る。
  - チャットとスレッドで分けて出す。入力中になった順に並ぶ。
  - `nextChangeAt` が期限を返す。上限を超えた新しい単位は捨てる。
- 間引き: 3秒以内の2回目は送らない。3秒後は送る。
- 文言: 1人・2人・3人以上。

## 5. 確認

- 単体テスト: `GroupTypingTest` 23件、チャット関連（`chat`・`ui.chat`）合わせて 243件、失敗0（iOS シミュレーター）。Android・Wasm のコンパイル成功。
- Web 版（ヘッドレス Chrome、2026-11-17）で、Buzz を模したリレー（AUTH 必須、kind 20002 は保存せず購読者へ配る）に参加して確かめた:
  - チャットで他人の入力中が「Bob Buzzさんが入力中…」と出る。2人は「Bob BuzzさんとCarolさんが入力中…」、3人は「Bob Buzzさんほか2人が入力中…」。
  - 約8秒で消える。その人のメッセージが届くと消える。
  - 自分の入力で kind 20002（content 空、`h` だけ）が送られる。入力を続けても3秒以内は送らず、3秒後の入力でもう1回送る。
  - スレッドの画面ではスレッドの入力中だけが出て、チャンネル直下の入力中は出ない。スレッドで入力するとルートへの `["e", ルート, "", "reply"]` が付く。
  - 入力中がほかのリレーへ送られないこと。
- 実機（2026-11-18、Android・秘密鍵ログイン、`png.communities.buzz.xyz`）で、Buzz 公式アプリとの間で両方向に表示されることを確かめた。`[Typing]` ログ（`util/PlatformLog.kt` の `isTypingTraceEnabled`）では、ToriNos の送信がリレーに受理されていた。
  - 最初は実機に実装前の版が入っていて動かなかった（端末のアプリの更新時刻で気づいた）。
  - チャンネルを開き直した直後の最初の入力は、認証の状態がまだ記録されていないので送らないことがある（5秒後の入力からは送れる）。
- 送信は、リレーの応答（受理・拒否）を待つようにした。拒否されたときは `[Typing]` ログに理由が出る。
- iOS の実機・外部署名器で送らないことは未確認。
