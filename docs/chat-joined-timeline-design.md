# 参加中グループのタイムライン 設計

- 作成日: 2026-11-18
- ステータス: 実装済み（単体テスト済み。エミュレーターでは切り替えと空の表示だけ確認。Buzz の実データでの確認は未）
- 目的: チャットタブで、参加中のすべてのグループ（Buzz・標準の NIP-29）の投稿を1つの一覧で読めるようにする。Google Chat のホームのように、スレッドは「元の投稿 + 最新の返信」の1行にまとめ、最後に動きがあった順に並べる。
- 関連: `docs/nip29-buzz-design.md`（チャットタブと Buzz 対応の全体）。

## 1. 画面

チャットタブの上部（ヘッダーの下）に切り替えを置く。ヘッダーでリレー・コミュニティを選んでいるときだけ出す（「すべて」と DM では出さず、グループの一覧を出す）。

```
[ グループ | タイムライン ]
```

- **グループ**: 今の一覧（グループごとに1行）。
- **タイムライン**: 会話ごとに1行。範囲は選んでいるリレーの参加中のグループ。
- 選んだ表示はアカウントごとに端末へ保存し、次に開いたときも使う（`chat.view.<pubkey>`）。

### 1.1 行（実際の投稿に近い形）

```
[#] welcome-everyone 💬
[avatar] 部長  14:44
         @ぺこ さん、ようこそ 👋 自己紹介・質問、気軽にどうぞ…（本文をそのまま。Markdown・画像も出す）
      ╰ [avatar] 部長  14:50
                 @N 修正しました。…
```

- 見出しはグループのアイコン（小）と名前。返信がある会話はスレッドの印を付ける。
- 元の投稿は、チャットの画面の発言と同じくアイコン・名前・時刻・本文（Buzz は Markdown と画像、標準はリンク付きの本文）。フォーラムの投稿・kind 11 は見出しを出す。
- 返信があれば、最新の返信を「╰」を付けて字下げし、同じ形（アイコンは小さめ）で出す。その下に「💬 返信 n件 ▸」（読めている返信の数）。
- 元の投稿が読めないときは「元の投稿を読み込めません」と出し、返信だけを出す。
- 会話の間は線で区切る。「今日」「昨日以前」で区切る（端末の日付で判定）。
- Buzz の画像は、グループの画面と同じく `/media/` に署名を付けて読む（外部署名器では押して許可）。
- 押したとき:
  - 返信のある会話、フォーラムの投稿、kind 11 → スレッド画面（`GroupThreadRoute`）。
  - 返信の無いチャットの投稿 → そのグループの画面（フォーラムのグループはフォーラムの画面）。
- 一番下に「さらに読み込む」。

### 1.2 グループの一覧の最新の発言

グループの一覧（「グループ」の表示）でも、最新の発言が Buzz のスレッドの返信なら、元の投稿の1行を上に出し、返信を「╰」を付けてその下に出す。ルートは一覧の読み込みのあとに `ids` で読み、端末の控え（`ChatListCache`）にも残す。読めなければ返信だけを出す（今までと同じ）。

## 2. 会話の単位

| 種類 | 会話のルート | 返信として数えるもの |
| --- | --- | --- |
| Buzz のチャット | `root`/`reply` の `e` タグが無い kind 9・40002 | `buzzThreadRootId` がそのルートの kind 9・40002 |
| Buzz のフォーラム | kind 45001 | kind 45003（`buzzThreadRootId`） |
| 標準のチャット | すべての kind 9（`q` 返信もスレッドにまとめず1行。返信先は読めていれば `replyTo` に入る） | なし |
| 標準のスレッド | kind 11 | kind 1111（`E` タグ） |

- 「最後の動き」= ルートと読めている返信の `created_at` の最大。
- 削除（作者の kind 5、管理者・リレーの kind 9005）と Buzz の編集（40003）は `GroupTimeline` と同じに反映する。ルートが削除された会話は出さない。
- ミュートした人の投稿は出さない。最新の返信がミュートした人なら、その前の返信を出す。ルートがミュートした人なら会話ごと出さない。
- Buzz の「スレッドから送信」したコピー（`buzz:sent-from-thread`）はトップレベルの投稿として出る（Buzz のチャンネルでもそう見えるため）。

`GroupTimeline` に `conversations()` を足して、1グループ分の会話を作る。全グループ分をまとめて並べるのは `JoinedTimeline`（純粋な関数）が行う。

## 3. 読み込み

リレーごとに並行して読む。参加中のグループの一覧と各リレーの鍵（NIP-11 の `self`）は、今の一覧の読み込み（`ChatTabViewModel`）が持っているものを使う。

1. **最近の投稿**: `kinds` = 上の表の種類すべて、`#h` = そのリレーの参加中のグループID、`limit` = 100。
2. **続き**（1 で読めたものについて、1回の要求にまとめる）:
   - 返信のルートで、まだ読めていないもの: `ids`。
   - ルートへの返信（返信の数と最新の返信）: `#e` = ルートID（Buzz）、`#E` = ルートID（kind 1111）、`limit` = 500。
   - 削除と編集: kind 5・9005・40003、`#e` = 読めた投稿の ID。
   - 管理者（kind 39001、リレーの鍵の署名）: 9005 を誰のものとして認めるか。
3. 一部のリレーが答えなくても、答えたリレーの分を出す。答えなかったリレーは行の上に「読めなかったリレーがあります」を出す（リレーの名前つき）。

### 3.1 リレーごとの範囲のずれ

リレーごとに `limit` 件を読むと、読めている期間がリレーで違う（よく動くリレーは数時間分、静かなリレーは数か月分）。そのまま混ぜると、よく動くリレーの古い部分が抜けたまま、静かなリレーの古い投稿が並んでしまう。

- `limit` いっぱいに返ってきたリレーについて、読めた最古の `created_at` を「そのリレーの下限」とする。
- 表示の下限 = 下限のうち最も新しいもの。「最後の動き」がこれより古い会話は、まだ出さない（`JoinedTimeline` で切る）。
- 「さらに読み込む」では、下限にかかっていたリレーだけを、そのリレーの最古を `until` にして読み足す（同じ秒を取りこぼさないよう、最古の秒を含める。`OlderPager` と同じ扱い）。

### 3.2 いつ読むか

- タイムラインに切り替えたとき、およびタイムラインを出したままタブに戻ってきたとき（今の一覧の `refreshJoined` と同じ時機）。
- 読み直しのときは前の結果を出したまま読み、そろったら差し替える。
- 配信（購読し続けること）はしない（初版）。

## 4. 初版でやらないこと

- 既読・未読の反映（タイムラインで読んでも、グループの未読は減らさない）。
- リアクションの表示。
- タイムラインからの返信・投稿。
- 端末への保存（開くたびに読む）。

## 5. テスト

- `GroupTimeline.conversations()`: Buzz のスレッドのまとめ、最新の返信、返信の数、ルートが無いとき、ルートの削除、フォーラム、標準の kind 9 と kind 11 / 1111、編集の反映、ミュート。
- `JoinedTimeline`: 複数グループの並べ替え、下限での切り捨て、「今日」の区切り、タップ先の判定。
