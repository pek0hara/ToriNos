# Buzz コミュニティの同期（kind 10009 の暗号化項目） 設計

- 作成日: 2026-11-19
- ステータス: 実装済み（単体テストのみ。Web 版・実機・実在のコミュニティでの確認は未実施）
- 関連: [nip29-buzz-design.md](nip29-buzz-design.md) の 5.5・6.4、[NIP-51](https://github.com/nostr-protocol/nips/blob/master/51.md)（kind 10009、暗号化項目）、[NIP-65](https://github.com/nostr-protocol/nips/blob/master/65.md)、[NIP-44](https://github.com/nostr-protocol/nips/blob/master/44.md)
- 目的: 参加中の Buzz コミュニティを、端末を替えたり入れ直したりしても ToriNos で復元できるようにする。所属は他の人に見せない。

## 1. 背景

- 今は Buzz コミュニティを端末にだけ保存している（`chat.buzzCommunities.<pubkey>`）。別の端末や入れ直したアプリでは、チャットタブに出てこない。
- kind 10002 には入れない。NIP-65 では印の無い `r` は「読み書き両方」の意味で、「読みも書きもしない」は表せない。入れると、ほかのクライアントが通常の投稿を Buzz のリレーへ送り、メンションを Buzz のリレーへ探しにいく。公開されるので所属も見える。
- 公開タグの kind 10009 にも入れない（所属が見えるため。nip29-buzz-design.md 6.4）。

## 2. 方針

- kind 10009 の **暗号化項目**（NIP-44 で自分宛て、`content` に JSON のタグ配列）に `["r", <BuzzリレーのURL>]` を入れる。同じリレーの `group` タグは入れない（Buzz のチャンネルは 10009 で管理しない）。
- 10009 を正とし、端末の保存は控えとして使う。合わせ方は「和集合」。消す同期は今回は扱わない（4.4）。
- 復元はチャットタブを開いたときに行う。起動時には何もしない。
- 復元の候補は NIP-11 で Buzz と確かめ、AUTH して読めるかでメンバーか確かめてから、端末の一覧に入れる。

## 3. 一覧の読み方

暗号化項目のうち、次をすべて満たす `r` を Buzz の候補とする。

1. URL を `normalizeRelayUrl` で正規化できる。
2. 暗号化項目にも公開タグにも、同じリレーの `group` タグが無い（標準の NIP-29 のグループに付く `r` と区別する）。

候補のうち、NIP-11 の `supported_extensions` に `buzz-*` があるものを Buzz のコミュニティとする（今の判定と同じ）。Buzz でないと分かったものは無視する（消さない）。`NotMember` と同じく、10009 の版が変わるまで確かめ直さない。

## 4. 合わせ方

`L` = 端末の一覧、`R` = 10009 の暗号化項目にある Buzz の候補。

### 4.1 10009 にだけあるもの（`R − L`）: 復元する

1. 「確認中」の集合に入れる。確認中のリレーは NIP-42 の AUTH を許す（自分で暗号化した一覧にしか無く、他人が書き込めないため、利用者が許可したものと扱う）。
2. NIP-11 で Buzz か確かめる。読めないときは確認中のまま、次にタブを開いたときに確かめ直す。
3. `checkBuzzMembership` で確かめる。
   - `Member`: 端末の一覧に入れる（`addBuzzCommunity`）。
   - `NotMember`（`not a relay member` と明示された）: 端末の一覧に入れない。10009 からは消さない（1つのリレーの答えで、ほかの端末の保存を壊さないため）。この判定は端末に控え、10009 の版（イベントの ID）が変わるまで確かめ直さない。
   - `Unknown`（時間切れ・署名の拒否など）: 確認中のまま、次にタブを開いたときに確かめ直す。
4. 確認中のリレーはチャットタブの一覧に「確認中」として出す。開くことはできない。

### 4.2 端末にだけあるもの（`L − R`）: 10009 へ書き足す

- 今使っている人の端末の保存も、これで 10009 へ移る。
- 書けなかったときは端末の一覧はそのままにし、次にタブを開いたときに書き直す。

### 4.3 参加したとき

- 参加の流れ（`ChatTabViewModel` の参加シート）で `BuzzMembershipCheck.Member` になったら、10009 の暗号化項目へ書き足す。
- `addBuzzCommunity` の時点では書かない。参加の確認に失敗すると端末の一覧から外す流れ（`removeBuzzCommunity`）があるため、確かめる前に書くと、参加できなかったコミュニティが残る。
- 書けなかったときも参加は成功とする（次にタブを開いたとき 4.2 で書き直す）。

### 4.4 消すこと（今回は扱わない）

- 今は Buzz コミュニティを「外す」画面が無い（あるのは端末ごとの非表示 `ChatHiddenRelaysStore` だけ。これは同期しない）。参加の確認に失敗したときの `removeBuzzCommunity` は、10009 へ書く前の取り消しなので同期は要らない。
- 外す画面を作るときは、端末に「前回 10009 と合わせた一覧」を控え、三者で比べる（ほかの端末で外したものを、この端末の 4.2 で書き戻さないため）。

## 5. 10009 の書き換え

既存の `updateList` に、暗号化項目へ Buzz の `r` を足す変更（`GroupsListChange.AddPrivateRelay` など）を加える。守ること:

1. 書く直前に読み直し、`listConfirmed` でなければ書かない（全リレーの答えがそろわないうちに、ほかの端末の一覧を上書きしないため。今のガードと同じ）。
2. 暗号化項目は**読めたときだけ**書き換える。今の `privateTags` は復号に失敗すると空を返すので、それを土台にすると、ほかのクライアントが入れた暗号化項目を消してしまう。暗号化項目を書き換えるときは、復号の失敗を空ではなく失敗として扱う（`content` が空のときだけ空から始めてよい）。
3. 暗号化項目にある未知のタグは保つ。既に同じ `r` があれば何もしない。
4. 公開タグには触らない。
5. 標準のグループを外すときの `withoutJoinedGroup` は、そのリレーの `group` が無くなると `r` も外す。端末の Buzz 一覧にあるリレーの `r` は外さない。
6. 一度に書くのは1回にまとめる（4.2 で複数あれば、まとめて1つのイベントにする）。

## 6. 外部署名器での確認の回数

- 外部署名器（NIP-46・NIP-07）では、今は利用者の操作のときだけ暗号化項目を読む（起動のたびに確認を出さないため）。チャットタブを開くのは利用者の操作なので、ここで読んでよい。
- それでも、タブを開くたびに確認を出さないよう、「最後に処理した 10009 の ID と、そこにあった候補」を端末に控え、同じ版なら復号せず控えの候補で合わせる。ToriNos が自分で書いた版は、書いた時点で中身が分かっているので、その ID を処理済みとして控える。
- 4.2 で書き足すには復号が要る。端末にだけあるものが無ければ復号しない。
- 秘密鍵・パスキーでは、確認が出ないので版にかかわらず読んでよいが、通信と処理を減らすため同じ控えを使う。
- 署名器が NIP-44 に対応しないとき（`SignerException.Unsupported`）は、同期を諦め、端末の保存だけで今までどおり動く。

## 7. 動く時機

- チャットタブの ViewModel の初期化（`ChatTabViewModel.init`）の、`account.start()` の後。引っ張って更新したときにも行う。
- `refreshJoinedGroups` が 10009 を読み終えるのを待ってから合わせる。答えがそろわず一覧が見つからないとき（`GroupsLoad.Retry`）は、4.1 も 4.2 も行わない。
- 処理は `ChatAccount` のスコープで行い、タブを離れても途中でやめない。同時に2回走らせない。

## 8. 端末に控えるもの（アカウントごと）

| キー | 中身 |
| --- | --- |
| `chat.buzzCommunities.<pubkey>` | 参加中の Buzz コミュニティ（今のまま） |
| `chat.buzzSync.state.<pubkey>` | 最後に処理した 10009 の ID と、そこにあった Buzz の候補（6）。同じ版なら復号せず、この候補で合わせる |
| `chat.buzzSync.notMember.<pubkey>` | 4.1 で `NotMember` だったリレーと、そのときの 10009 の ID |

確認中の集合はメモリだけに持つ。

## 9. 10009 に入らない情報

| 情報 | 復元のしかた |
| --- | --- |
| 表示名 | NIP-11 から取る（今と同じ） |
| 規約に同意した版 | 持たない。メンバーと確かめられたら、サーバーでは同意済み |
| 参加処理中の控え・招待コード | 同期しない（招待コードは秘密情報） |

## 10. テスト（先に書く）

純粋関数に切り出して検証する。

1. 候補の取り出し: 暗号化項目の `r` のうち、同じリレーの `group` が公開・暗号化のどちらにも無いものだけ。正規化と重複。
2. 合わせ方: `R − L` は確認へ、`L − R` は書き足しへ、`NotMember` の控えがあり版が同じなら確かめない、版が変われば確かめ直す。
3. 書き換え: 暗号化項目への追加で未知のタグを保つ、既にあれば変えない、公開タグは変えない、まとめて1回。
4. 復号に失敗したら書き換えない（空の一覧で上書きしない）。`content` が空なら空から始める。
5. `withoutJoinedGroup` が、Buzz のリレーの `r` を残す。
6. 一覧の答えがそろわないとき（`listConfirmed` でない）は書かない、合わせない。
7. 確認中のリレーで AUTH が許される、確認が終わったら（`NotMember`）許されなくなる。
8. 外部署名器で、同じ版なら復号しない、自分で書いた版も復号しない。

## 11. 検証

- 単体テストと全体テスト、Android・iOS・Wasm のコンパイル。
- Web 版（ヘッドレス）で、模したリレーと Buzz コミュニティを使い、(1) 端末Aで参加 → 10009 の暗号化項目に `r` が入る、(2) 保存を消した端末Bでチャットタブを開く → 確認中 → 一覧に出る、(3) メンバーでない候補は出ない、(4) 既存の端末保存だけの状態からタブを開くと 10009 へ移る、を確かめる。
- `[Relay]` ログで、確認中のリレー以外へ AUTH していないこと、10009 を1回だけ送ったことを確かめる。

## 12. 懸念

- ほかのクライアントが 10009 の暗号化項目の `r` を「グループを探すリレー」として読むと、Buzz のリレーへ接続しにいく可能性がある。メンバーなら問題無く、メンバーでなければ AUTH で止まるだけ。
- Buzz 本家のクライアントは 10009 を使わないので、本家との同期にはならない（ToriNos 同士の復元が目的）。

## 13. 確認の記録（2026-11-19）

- 単体テスト: 全体 2362件、失敗0。Android・iOS・Wasm のコンパイル、`verifyNoDirectProfileSubscriptions` 成功。
- Web 版（ヘッドレス Chrome）。通常のリレーは模擬にして、受け取った kind 10009 を端末をまたいで返した。Buzz は模擬のリレー（`buzz.test`、メンバー）、メンバーでない Buzz（`buzz2.test`）、Buzz でないリレー（`plain.test`）を用意した。実リレーには接続していない。
  1. 端末にだけ Buzz コミュニティがある状態でタブを開くと、10009 を1回送った。公開タグは空、暗号化項目は `[["r","wss://buzz.test"]]`。タブを開き直しても送り直さない。
  2. 空の端末で同じ鍵にログインしてタブを開くと、`buzz.test` が一覧に入った。`buzz2.test`（not a relay member）と `plain.test`（Buzz でない）は入らず、控えに記録された。暗号化項目に `group` のある `plain2.test` は候補にならない。この端末は何も送らない。
  3. NIP-11 が時間切れの間は「確認中」のまま残り、NIP-11 の失敗の控え（2分）が切れた後にタブを開き直すと一覧に入った。開き直しで、メンバーでない・Buzz でないものは確かめ直さない。
  4. ほかのクライアントが入れた暗号化項目（未知のタグ、標準のグループ）は、書き足しても保たれた。
- 確認中に見つけて直したこと: NIP-11 を読めないときに「確認中」から外して一覧から消えていた（設計どおり残すように直した）。10009 から消えた候補が「確認中」に残り続ける可能性（合わせるたびに今回の候補で置き換える）。
- 未確認: 参加シートで参加したときの書き込み（4.3。招待の模擬が要る）、外部署名器（NIP-46・NIP-07）での確認の回数、Android・iOS の実機、実在の Buzz コミュニティ。
- パスキーが解錠されていない間は復号も署名もできないので、同期は何もせずに終わる。解錠後にタブを開き直すと行う。
