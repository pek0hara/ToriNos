# アカウント切り替え時のデータ保護

## 対象

旧ミュート・NGワードの重複移行、リレー設定復元前の購読開始、未送信のミュート変更の消失を修正する。

## セッション開始

`AccountSessionManager` がセッションを `Active` として公開する前に、次を順番に完了する。

1. `RelayStore.activateAccount(pubkey)` でアカウント別のリレーと選択URLを復元する。
2. `NostrRepository.routingRelayUrls` が復元した設定と一致するまで待つ。待機の上限は10秒。
3. ミュート・NGワードのローカルキャッシュを読み込む。
4. `Active` に遷移し、画面・Repository・ネットワーク同期を開始する。

匿名セッションもリレー復元を同じ経路で行う。準備失敗時は既存のロールバック経路で元アカウントの設定を復元する。リレー選択の補正は `RelayStore` に集約し、画面からは補正・保存しない。ストア自身の起動時ロードは、セッション開始処理が先にロードを完了していれば繰り返さない。

## 旧キャッシュの移行

`PrivateMuteListStorage` が共通旧キーを扱う。移行先の公開鍵を `private_mute_list_legacy_owner_v1` に先に保存する。

- 移行先以外のアカウントは旧キーを読まない。
- アカウント別キャッシュが既にあれば、それを優先する。
- アカウント別キャッシュの保存成功後に、v1キャッシュと `muted_pubkeys`／`ng_words` のすべてを削除する。
- 保存や削除が中断されても移行先の記録は残り、別アカウントへの複製を防ぐ。
- 元データには公開鍵の情報がないため、移行先は最初にこの移行処理を実行したアクティブアカウントとする。

## ローカル変更と送信

キャッシュに編集の `revision`、`hasPendingChanges`、再送用の署名済み `pendingEvent` を追加する。既存JSONは省略値で読める。旧実装でローカル編集として保存されたキャッシュ（更新時刻あり・元イベントIDなし）も未送信として扱う。

- ローカル編集は未送信として即座にメモリへ反映し、送信前に永続化する。
- メモリの変更、ディスク保存、送信、取得はそれぞれ直列化する。通信待ち中も新しい編集を保存できる。
- 未送信変更があるとき、取得結果はリストを上書きせず、次の署名時刻の基準だけ更新する。
- イベントの署名時刻は、既知のリレーイベントより後にする。
- 署名済みイベントも送信前に保存する。送信成功は少なくとも1リレーからの受理確認で判定する。
- 送信完了時に編集の世代とイベント時刻を確認し、後続の編集やより新しいリレーイベントがあれば未送信状態を残す。
- 失敗・中断時は未送信状態を維持する。セッション開始時と手動更新時に再送する。

## セッション終了

セッションの署名機能を無効化した後、ミュートストアへの編集を閉じ、最新のローカル状態の保存完了を待つ。その後に購読とセッションのジョブを終了する。送信完了は待たない。保存に失敗した場合は切り替えを失敗として扱い、終了処理自体は必ず実行する。元アカウントへ復帰する際は、旧セッションの未保存編集もメモリから引き継ぐ。匿名状態への準備まで失敗した場合も、終端状態への遷移とエラー表示を保証する。
